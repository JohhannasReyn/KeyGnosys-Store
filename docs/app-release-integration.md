# App release integration (KeyGnosys → keygnosys.com)

The website reads release data at build time. Each published, non-prerelease release of
`JohhannasReyn/KeyGnosys` **must** attach `keygnosys-release.json` that validates against
https://keygnosys.com/schemas/keygnosys-release-v1.json (spec §5.2). If it doesn't, the site build fails and the
previous version stays live.

Rules:
- Generated by the release workflow, never hand-written.
- `commit` is the full SHA the artifacts were built from; `buildRunUrl` is that workflow run.
- Every `file` is attached to the same release with the same `size`; exactly one `primary` per platform.
- `platform` is `windows` or `linux`. Adding a platform requires a website schema change and a real build.

Sketch of the app-side steps (implemented in the app repo, not here):

    permissions: { contents: write, id-token: write, attestations: write }
    steps:
      # …build artifacts into ./out…
      - uses: actions/attest-build-provenance@<sha>   # enables `gh attestation verify`
        with: { subject-path: 'out/*' }
      - run: <app script> out/ > keygnosys-release.json   # emits the manifest from ./out
      - run: npx --yes ajv-cli@5 validate --spec=draft2020 -s schema.json -d keygnosys-release.json
        # schema.json downloaded from https://keygnosys.com/schemas/keygnosys-release-v1.json
      - run: gh release upload "$TAG" out/* keygnosys-release.json
      - run: gh api repos/JohhannasReyn/KeyGnosys-Store/dispatches -f event_type=app-release
        env: { GH_TOKEN: ${{ secrets.SITE_DISPATCH_TOKEN }} }   # fine-grained PAT scoped to KeyGnosys-Store: Contents read/write

Docs: user docs live in `docs/guide/` (Markdown, images from `docs/images/`). The site publishes them from the
release's `commit`, so doc fixes ship with the next release. No `<script>`, inline handlers, iframes or remote images.
